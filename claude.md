# The Actors Office (TAO) — Developer Context for Claude

This file provides Claude with the core system knowledge needed to work on TAO code, features, technical planning, and debugging.

---

## Overview

TAO is a ColdFusion + MSSQL web application that helps actors manage the administrative side of their careers. The system includes scheduling, contact management, reminders, project tracking, relationship workflows, and mobile extensions.

Primary technologies:

* ColdFusion (backend controllers and views)
* MSSQL Server (production DB: `abo`, test DB: `abod`)
* Frontend: HTML/JS/CSS with AJAX for dynamic operations
* Potential mobile app via Flutter

User persona: actors using TAO to stay organized, track contacts, follow up after auditions, and maintain professional relationships.

---

## Key Modules and Responsibilities

### 1. Contacts

Central database of Casting and Industry contacts. Each contact can be linked to:

* Notes
* Systems (Targeting, Follow-Up, Maintenance)
* Notifications
* Events (auditions, meetings)
* Custom fields and relationship metadata

### 2. Relationship Systems

Actors take structured steps to build and maintain relationships. Systems include:

* Targeting
* Follow-Up
* Maintenance
  Each system has actions defined in `fuactions`, customized per user in `actionusers`.

Workflow tables:

* `fusystems` — master system definitions
* `fusystemusers` — per-contact per-user system instances
* `funotifications` — individual actionable items generated by systems

---

## Notification Engine

Each action becomes a `Pending` notification with a `notstartdate`.
Completion flow:

1. User completes a notification.
2. System schedules next action or creates recurring items.
3. When all actions are done, system may auto-start a Maintenance system.

Reminders:

* Driven by daily checks of `notstartdate <= GETDATE()`
* Surfaces: dashboard, email, push (future)

---

## Action Lifecycle

Actions have:

* Initial delay (`actionDaysNo`)
* Recurrence (`actionDaysRecurring`)
* Uniqueness rules (`isUnique`) to prevent repeats

On user account creation, `actionusers` is populated as a per-user override table for scheduling.

---

## Event System

Auditions and meetings are stored as events and can trigger Follow-Up and Maintenance workflows.
Events include:

* Casting info
* Submission notes
* Appointment data

## Technical Stack Notes

### ColdFusion

* Uses CFML tags + script syntax
* Data source: `reach`
* Heavy use of `<cfquery>` with `cfqueryparam`
* AJAX endpoints via `/ajax/...`

### MSSQL

* Tables use `int`, `bit`, `datetime`, `varchar(Max)` for text fields
* Business logic enforced via ColdFusion

### Flutter (future)

* Will wrap core TAO flows: contact management, reminders, event scheduling
